# 🌟 Возможности AutoStars

## Основной функционал

### 🤖 Автоматизация
- Мониторинг заказов FunPay
- Извлечение username и количества Stars
- Поиск получателя через Fragment
- Получение актуальной стоимости покупки
- Формирование transaction payload Fragment
- Оплата покупки через TON Wallet V4R2
- Проверка транзакции через Toncenter
- Завершение заказа только после подтверждения транзакции
- Защита от повторной обработки завершённых и неопределённых заказов
- Опциональный автоматический возврат однозначно неуспешного заказа

### 🤖 Автоответчик
- Работа через `FunPayAPI.Runner`
- Ответы по ключевым словам
- Точное совпадение
- Regex
- Настройка задержки
- Cooldown отдельно для каждого чата
- Защита от ответа на собственные сообщения
- Переменные `{username}` и `{chat_id}`
- Настройка через GUI

### 📱 Telegram
- Уведомления администратора
- Уведомления об успешных выдачах
- Уведомления об ошибках
- Команды `/start` и `/help`

### 🎨 GUI
- Запуск и остановка системы
- Просмотр статистики
- История операций
- Редактирование конфигурации
- Отдельная настройка автоответчика
- 12 готовых тем оформления

## 💳 Платёжная система

Используется логика из исходного `FragaStars.py`:

- Fragment API для поиска получателя
- Fragment API для создания покупки
- `Ref ID` из payload транзакции
- `tonutils` и `TonapiClient`
- Wallet V4R2
- TON-перевод с комментарием
- Проверка результата через Toncenter

## 🔒 Надёжность

- SQLite вместо JSON-базы для рабочих данных
- WAL-режим SQLite
- Защита уникальности транзакции
- Статусы `completed`, `failed`, `invalid`, `processing`, `unknown`
- Блокирующие сетевые вызовы вынесены из основного asyncio event loop
- Отдельный поток для FunPay автоответчика
- Логирование в консоль и `autostars.log`
- Корректная остановка фоновых задач

## ⚠️ Важное ограничение

Если TON-транзакция была отправлена, но её подтверждение не удалось получить, заказ получает статус `unknown` и автоматически не повторяется. Перед повторной обработкой необходимо проверить транзакцию вручную.
